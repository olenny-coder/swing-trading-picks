▲ Swing Trading Picks — Free Cloud Deployment

A step-by-step guide to hosting the app for $0 using Vercel + Render + Neon + GitHub Actions.

The free stack

PieceServiceCostNotes
Frontend (Next.js)VercelFreeAuto-deploys from GitHub
Backend (FastAPI)RenderFree web serviceSleeps after ~15 min idle; wakes on request (~30–60 s cold start)
DatabaseNeon (or Supabase)Free PostgresNo expiry, generous limits
Daily 8:30 PM SGT pullGitHub ActionsFreeRuns the cron even when the backend is asleep
Why GitHub Actions for the schedule? Render's free tier sleeps the backend when idle, so the built-in scheduler won't fire reliably. GitHub Actions runs on its own schedule and writes directly to the shared Postgres database.

Step 0 — Prerequisites

You need:

  • A GitHub account and git installed (git-scm.com).
  • Free accounts on Vercel, Render, and Neon (no credit card needed).
  • Your Alpaca API keys.

Push the project to GitHub first:

cd "C:\Users\Spare Parts\Swing Trading Picks"
git init
git add .
git commit -m "Initial commit"
# create an empty repo on github.com, then:
git remote add origin https://github.com/YOUR-USERNAME/swing-trading-picks.git
git branch -M main
git push -u origin main

Step 1 — Neon (free Postgres database)

  1. Sign in at neon.tech → Create project.
  2. Copy the connection string. It looks like:
    postgresql://user:pass@ep-xxx.aws.neon.tech/neondb?sslmode=require
  3. Convert it for SQLAlchemy by inserting +psycopg2:
    postgresql+psycopg2://user:pass@ep-xxx.aws.neon.tech/neondb?sslmode=require

Keep this string — you'll set it as DATABASE_URL in two places (Render and GitHub).

Step 2 — Render (backend)

  1. Sign in at render.com → New → Web Service.
  2. Connect your GitHub repo.
  3. Configure:
    • Root Directory: backend
    • Runtime: Docker (auto-detects backend/Dockerfile)
    • Instance Type: Free
  4. Set environment variables:
KeyValue
DATABASE_URLyour Neon postgresql+psycopg2://… string
SECRET_KEYa long random string
DATA_PROVIDERauto
DISABLE_SCHEDULERtrue
ALPACA_API_KEYyour Alpaca key (or enter later in the app)
ALPACA_SECRET_KEYyour Alpaca secret
ALPACA_PAPERtrue
CORS_ORIGINShttps://YOUR-APP.vercel.app
  1. Click Deploy (first build takes a few minutes).
  2. Note the URL (e.g. https://swing-api.onrender.com) and test it at /api/health.

Step 3 — Vercel (frontend)

  1. Sign in at vercel.com → Add New → Project → import the repo.
  2. Configure:
    • Root Directory: frontend
    • Framework: Next.js (auto-detected)
  3. Set environment variable:
KeyValue
API_URLhttps://swing-api.onrender.com (your Render URL)
  1. Deploy. Vercel gives you https://YOUR-APP.vercel.app.
  2. Open it and sign in with admin / changeme (change these — see Step 5).

Step 4 — GitHub Actions (daily 8:30 PM SGT pull)

The workflow already exists at .github/workflows/daily-cron.yml (scheduled 30 12 * * * UTC = 8:30 PM Singapore time).

Add these repository secrets (GitHub → Settings → Secrets and variables → Actions):

SecretValue
DATABASE_URLyour Neon connection string
SECRET_KEYthe same secret you set on Render
ALPACA_API_KEYyour Alpaca key
ALPACA_SECRET_KEYyour Alpaca secret
DATA_PROVIDERauto (optional)

Then run it once manually (Actions → Daily signal generation → Run workflow) to verify signals appear in the app.

Step 5 — Change the default admin password

Set these on Render (backend) and restart:

KeyValue
ADMIN_USERNAMEyour username
ADMIN_PASSWORDa strong password

Caveats & tips

  • Cold start: Render free sleeps after ~15 min idle; the first request wakes it (30–60 s).
  • Both schedulers: keep DISABLE_SCHEDULER=true on Render so it doesn't fight GitHub Actions.
  • Options data: put-option contract recommendations need an Alpaca options subscription or a Polygon.io key; without them, bearish setups still appear with underlying levels.
  • Public repo warning: never commit .env or real secrets. Keys entered via the app's Settings UI are stored encrypted in the database.
